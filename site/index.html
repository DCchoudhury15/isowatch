PostgreSQL 18 · OpenTelemetry

Your database lost a write. IsoWatch shows you the trace that did it.

Under PostgreSQL's default isolation level, two concurrent requests can silently overwrite each other. No error, no log line. IsoWatch catches lost updates and write skew as they happen in live traffic and adds an anomaly span to the guilty trace.

02 / the alertisowatch.anomaly

Facts, not guesses. The SQL, the traces and the fix.

The alert lands in your tracing tool (Jaeger, SigNoz, Grafana Tempo) as a span linked to every request involved.

ANOMALY lost-updatepublic.accounts(1)
Lost update on public.accounts(1): a transaction wrote this row based on an old read
and replaced 1 newer version(s) it never saw.
  deposit (txn 75d0a9c6) in trace 77c63e5e read     version 3449: SELECT balance FROM accounts WHERE id = $1
  deposit (txn 95392cf0) in trace 3eed3a5c replaced version 3449: UPDATE accounts SET balance = $1 WHERE id = $2
  deposit (txn 95392cf0) in trace 3eed3a5c wrote    version 3450: UPDATE accounts SET balance = $1 WHERE id = $2
  deposit (txn 75d0a9c6) in trace 77c63e5e replaced version 3450: UPDATE accounts SET balance = $1 WHERE id = $2
  fix: add FOR UPDATE to the SELECT, or write SET balance = balance + $1,
       or run these transactions at SERIALIZABLE and retry on error 40001.
03 / the pipelineapp → collector

From your pgx transaction to an anomaly span.

Two hidden columns on the way in, a dependency graph on the way out. The checking model is Adya's, the same one the Jepsen tool Elle uses.

capture

Track what you read

On SELECT the row's xmin is added as a hidden column. Your code gets exactly the columns it asked for.

capture

Track what you replaced

Writes get RETURNING old.xmin, new.xmin, new in PostgreSQL 18. Now every overwrite has proof.

collector processor

Find the cycle

Transactions become OTel spans. The processor builds the graph and looks for cycles across traces, in any order they arrive.

protect

Fix only where it hurts

Once it sees an anomaly, IsoWatch can run just those named transactions at SERIALIZABLE and retry them.

05 / try itdocker only

See it in two minutes.

Starts PostgreSQL 18, Jaeger, the IsoWatch collector and a tiny bank with the bug. Then open Jaeger and look for the red traces.

bash
$ git clone https://gitlab.com/divyanshuchoudhury51/isowatch && cd isowatch
$ make demo-up
$ make demo-load              # 200 concurrent deposits, buggy code
$ make demo-load MODE=-auto   # same code, protected by IsoWatch
