Your database lost a write. IsoWatch tells you which requests did it.

Concurrent requests can silently corrupt data under PostgreSQL's default isolation level. No error, no log line. IsoWatch catches lost updates and write skew as they actually happen in live traffic, names the traces involved, and tells you how to fix them.

What you get instead of silence

An alert in your tracing tool (Jaeger, SigNoz, Grafana Tempo) with the facts, the SQL, the traces and the fix.

ANOMALY lost-update: Lost update on public.accounts(1): a transaction wrote this row
based on an old read and replaced 1 newer version(s) it never saw.
    deposit (txn 75d0a9c6) in trace 77c63e5e read     accounts(1) version 3449: SELECT balance ...
    deposit (txn 95392cf0) in trace 3eed3a5c replaced accounts(1) version 3449: UPDATE accounts ...
    deposit (txn 95392cf0) in trace 3eed3a5c wrote    accounts(1) version 3450: UPDATE accounts ...
    deposit (txn 75d0a9c6) in trace 77c63e5e replaced accounts(1) version 3450: UPDATE accounts ...
    fix: add FOR UPDATE to the SELECT, or write SET balance = balance + $1,
         or run these transactions at SERIALIZABLE and retry on error 40001.

How it knows

Every row version in PostgreSQL carries xmin, the id of the transaction that wrote it. IsoWatch reads that number quietly. It reports facts, not guesses.

01 / read

Which version you read

On SELECT, IsoWatch adds the row's xmin as a hidden column. Your code gets exactly the columns it asked for.

02 / write

Which version you replaced

On UPDATE, INSERT and DELETE, it adds RETURNING old.xmin, new.xmin, new in PostgreSQL 18.

03 / check

Find the cycle

Read 100 but replaced 150 means a write was overwritten unseen. IsoWatch builds Adya's dependency graph and looks for cycles, in your app or in an OpenTelemetry Collector.

protect

Fix only where it hurts

Once it sees an anomaly, IsoWatch can run just those named transactions at SERIALIZABLE and retry them. Everything else stays fast.

trace

Linked to your requests

Alerts are isowatch.anomaly spans added to the trace of the request, with links to the other requests involved.

ignore

Accept what is fine

Some races do not matter, like "last seen" timestamps. Ignore them by table or by transaction name.

See it in 2 minutes

Docker only. Starts PostgreSQL 18, Jaeger, the IsoWatch collector and a small demo bank with the bug.

# clone and start everything
git clone https://github.com/DCchoudhury15/isowatch && cd isowatch
make demo-up
# 200 concurrent deposits through the buggy code
make demo-load
# then open http://localhost:16686 and look for the red traces
